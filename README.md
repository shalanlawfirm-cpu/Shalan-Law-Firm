# الخادم الخلفي — نظام مكتب شعلان للمحاماة

خادم Node.js + Express حقيقي، بقاعدة بيانات SQLite، يوفر تسجيل دخول آمن (كلمات مرور مشفّرة + JWT)، وبيانات تتزامن بين كل المستخدمين والأجهزة — بديل حقيقي لتخزين المتصفح المحلي المستخدم في النموذج التجريبي.

## ⚠️ ملاحظة مهمة عن رابط claude.ai

الواجهة المتصلة فعليًا بالخادم (`backend/public/index.html`) **لا يمكن نشرها كرابط Artifact على claude.ai** وتوقّع أن تعمل، لأن سياسة الأمان داخل تلك الصفحات تمنع أي اتصال شبكي بخادم خارجي غير خوادم Anthropic. الرابط التجريبي السابق (`law-office.html`) يعمل هناك فقط لأنه لا يتصل بأي خادم — كل بياناته محلية داخل المتصفح.
هذه النسخة الجديدة مصمَّمة لتعمل عند نشرها على استضافة حقيقية (Render/Railway/خادمك الخاص)، حيث الواجهة والخادم على نفس النطاق ولا قيود عليهما.

## 0) الآن يوجد واجهتان في المشروع

- `law-office.html` (الأصلية) — نموذج عرض سريع بلا خادم، يصلح فقط كرابط Artifact للمعاينة الفردية.
- `backend/public/index.html` (الجديدة) — الواجهة **الحقيقية المتصلة بالخادم**، وهي التي يقدّمها الخادم نفسه لكل من يفتح رابط استضافتك.

## 1) التشغيل محليًا

```bash
cd backend
npm install
cp .env.example .env   # ثم عدّل القيم داخل .env، خصوصًا JWT_SECRET وكلمة مرور الإدارة
npm start
```

افتح `http://localhost:4000` مباشرة — هتلاقي الواجهة الكاملة شغّالة ومتصلة بالخادم فعليًا (تسجيل، دخول، طلبات، مهام، سداد...). جرّب `http://localhost:4000/api/health` للتأكد أن الـ API نفسه يستجيب.

**حساب الإدارة الافتراضي**: رقم الهاتف وكلمة المرور اللي حطيتهم في `.env` (`ADMIN_PHONE` / `ADMIN_PASSWORD`) — بيه تقدر تدخل كإدارة/استقبال، وتضيف موظفين من تبويب "الموظفون".

## 2) أهم نقاط الوصول (API)

| العملية | الطريقة | المسار | الصلاحية |
|---|---|---|---|
| تسجيل حساب جديد | POST | `/api/auth/register` | عام |
| تسجيل الدخول | POST | `/api/auth/login` | عام |
| قائمة الخدمات | GET | `/api/requests/services` | عام |
| إنشاء طلب استشارة/عمل | POST | `/api/requests` | مسجّل دخول |
| عرض الطلبات | GET | `/api/requests` | صاحب الطلب / الإدارة |
| تحديد الرسوم | PATCH | `/api/requests/:id/fee` | إدارة |
| الإبلاغ عن تحويل مبلغ | POST | `/api/requests/:id/mark-paid` | صاحب الطلب |
| تأكيد استلام السداد | POST | `/api/requests/:id/confirm-payment` | إدارة |
| تحويل الطلب إلى قضية | POST | `/api/requests/:id/convert` | إدارة |
| عرض قضاياي / كل القضايا | GET | `/api/cases` | موكّل / إدارة |
| إسناد مهمة جديدة | POST | `/api/cases/:id/tasks` | إدارة |
| عرض مهامي | GET | `/api/tasks/mine` | موظف / إدارة |
| إضافة تعليق على مهمة | POST | `/api/tasks/:id/comments` | موظف / إدارة |
| قائمة الموظفين | GET | `/api/users?role=staff` | إدارة |
| إضافة موظف/محامٍ جديد | POST | `/api/users` | إدارة |

كل طلب (عدا التسجيل والدخول) يحتاج الترويسة:
```
Authorization: Bearer <token>
```
والـ token يُستلم من رد `/api/auth/login` أو `/api/auth/register`.

## 3) ربط الواجهة الأمامية ✅ تم

`backend/public/index.html` الآن متصلة فعليًا بكل مسارات الـ API أعلاه عبر `fetch()`. التوكن يُحفظ في `localStorage` (آمن هنا لأن الصفحة ليست Artifact بل مستضافة على نطاقك الخاص). لو استضفت الواجهة على نطاق منفصل عن الخادم، عدّل متغيّر `API_BASE` أعلى ملف `index.html` ليشير لعنوان الخادم الكامل (مثال: `https://api.shalanlawfirm.com`).


## 4) الاستضافة المجانية الموصى بها

**التوصية: Render.com (للخادم) + Supabase (لقاعدة بيانات دائمة)**

المشكلة: معظم الاستضافات المجانية (بما فيها Render المجانية) تستخدم تخزين "مؤقت" (ephemeral) — أي ملف قاعدة بيانات SQLite هيتمسح مع كل إعادة تشغيل للخادم. الحل المجاني الموثوق:

1. **استضافة الخادم**: [Render.com](https://render.com) — خطة Free فيها:
   - نشر مباشر من GitHub مجانًا.
   - الخادم "ينام" بعد 15 دقيقة بدون طلبات، ويستيقظ تلقائيًا عند أول طلب (تأخير بضع ثوانٍ فقط).
   - بديل: [Railway.app](https://railway.app) (رصيد مجاني شهري محدود) أو [Fly.io](https://fly.io) (طبقة مجانية بها تخزين دائم Volumes).

2. **قاعدة بيانات دائمة**: بما إن SQLite لا يصلح على Render المجانية، الخيار الأفضل المجاني هو **Postgres** بدل SQLite:
   - [Supabase](https://supabase.com) — قاعدة Postgres مجانية حتى 500 ميجابايت، دائمة، ولا تُمسح.
   - يتطلب هذا تعديل بسيط في `src/db.js` لاستخدام حزمة `pg` بدل `better-sqlite3` (يمكنني تجهيزه لو قررت المضي في هذا الخيار).

**خلاصة عملية**: للتجربة والعرض على العميل الآن، شغّل الخادم كما هو (SQLite) على جهازك أو على Render مباشرة — يعمل بشكل كامل. لما يبقى عندك مستخدمين حقيقيين ومستمرين، انقل قاعدة البيانات لـ Supabase حتى لا تفقد البيانات مع كل إعادة تشغيل.

## 5) الخطوة التالية لبوابة الدفع الفعلية

حاليًا السداد "يدوي مؤكَّد بشريًا" (العميل يبلغ بالتحويل، والاستقبال يؤكد). لتفعيل تحقق تلقائي حقيقي لاحقًا: بوابات مصرية مناسبة هي **Paymob** أو **Fawry**، وكلتاهما توفر SDK/Webhook يمكن دمجه في `src/routes/requests.js` بدل مسار `mark-paid` اليدوي — أقدر أساعدك بهذا لاحقًا لو فتحت حساب تاجر مع إحداهما.
